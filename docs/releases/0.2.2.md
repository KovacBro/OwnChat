## OwnChat 0.2.2

Hotfix for a regression introduced in 0.2.0: WorkBuddy conversations failed with

```
请求内容不合法，请重试（code 11101，requestId …）
```

### What happened

The upstream describes each model's reasoning effort as an object
(`{supportedEfforts, defaultEffort, canDisableThinking}`). Since 0.2.0 that object
was copied verbatim into the `reasoning_effort` field of the request body, and the
API rejects anything that is not a string.

### Fixed

- Only a **string** is ever sent as `reasoning_effort`; the object form is dropped.
- The type check exists in three places — model-list merge, request assembly, and
  both protocol adapters — so a future miss in one layer cannot leak it again.
- Stored data is cleaned on load: an object left by 0.2.0 / 0.2.1 is reset to
  empty. No manual edit or model refresh is needed.

### Verified

Same account, same model, after the fix: 21 models listed, streaming replies
returned, zero error events. Before the fix the same call returned `code 11101`.

### Notes

- Only affects WorkBuddy users who upgraded to 0.2.0 or 0.2.1. 0.1.0 is unaffected.
- Install over the previous version; `data/` is preserved.

> The installer is still not code-signed. SmartScreen may show “Unknown
> publisher”; verify `SHA256SUMS.txt`.
